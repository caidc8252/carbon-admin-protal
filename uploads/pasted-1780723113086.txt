# Devices · 数据模型差异分析（设备数据模型 vs 现有 Devices→Devices 功能）

> 日期：2026-06-06
> 对比双方：
> - **新模型** —— 业务方提供的设备数据定义：`DEVICE / DEVICE APPLICATION / DEVICE EVENT / DEVICE INFO / DEVICE EXTEND / BATTERY INFO / DEVICE APPLICATION STATISTIC / DEVICE STATISTIC / STORE`
> - **现有代码（真源）** —— `devices-fleet.jsx`（列表 + 详情四个 Tab + 派生 helper）+ `devices-list-search.jsx`（列表搜索/列预设覆盖）
> 性质：**差异梳理 + 改造决策依据**。本文不含代码改动，待业务方确认后再实施。
> 约束（业务方指示）：
> 1. 不改 Devices 已有的样式风格与栏目布局；
> 2. 功能下所有模块的数据不能超越模型定义 —— **超出模型的字段提出删除**；
> 3. **归属本栏目但模型有、UI 缺的字段提出补充**；
> 4. 终端↔商户/门店关系尚未充分定义、可能变化 —— 只关注"关系"本身，不展开其它无关字段。

## 1. 现有设备对象（seed 真源）字段 → 模型映射

现有 `DEVICES_SEED` 每台设备的形状：

```js
{ sn, model, os, firmware, buildNumber, activatedAt, createdAt, lastSeenAt,
  state, merchantId, storeId, imei, macAddress,
  storage:{total,used}, battery:{level,health},
  hardware:{root,devMode,securityWarnings[]},
  network:{ sim:{enabled,carrier}, ethernet:{enabled}, wifi:{enabled,ssid} },
  settings:{timezone,language,autoTimezone,autoTime},
  apps:[{id,name,version,installedAt,system}] }
```

| 现有字段 | 模型对应 | 结论 |
|---|---|---|
| `sn` | DEVICE.DEVICE SN | ✅ |
| `model` | DEVICE.MODEL CODE | ✅ |
| `os` ("Android 14") | DEVICE.OS VERSION / DEVICE INFO.OS+OS VERSION | ✅ |
| `firmware` | DEVICE.FIRMWARE VERSION | ✅ |
| `buildNumber` ("8.2.1.127.prod") | — | 🔴 **超模型** → 删除，或并入 DEVICE EXTEND.VERSION INFO |
| `activatedAt` | DEVICE.ACTIVE TIMESTAMP | ✅ |
| `createdAt` | DEVICE EXTEND.CREATE TIMESTAMP（DEVICE 本身只有 UPDATE/ACTIVE） | ✅（口径需确认） |
| `lastSeenAt` | DEVICE EXTEND.UPDATE TIMESTAMP（决策：以此为准） | ✅（取自 EXTEND.UPDATE TIMESTAMP） |
| `state` = active/inactive/pending | DEVICE.STATUS = 1正常/0锁定/9待激活 | 🟠 **语义错位**（见 §4.1） |
| `merchantId` / `storeId` | 关系：DEVICE.PARTNER ID（所有者）+ STORE 绑定 | 🟡 关系字段，保留（见 §5） |
| `imei`（单值） | DEVICE INFO.SIM SLOTS[].IMEI（每卡槽） | 🟠 模型为双卡槽多值（见 §4.2） |
| `macAddress` | —（模型无设备级 MAC） | 🔴 **超模型** → 删除或核实 |
| `storage{total,used}` | DEVICE INFO.STORAGE Capacity{total,used,base} | ✅ |
| `battery{level,health}` | BATTERY INFO.BATTERY AVAILABLE + HEALTH STATUS/BATTERY HEALTH | ✅（极简化，模型远更丰富，见 §3） |
| `hardware.root` | DEVICE.ROOT MODE / DEVICE EXTEND.SYSTEM SECURITY.IS ROOTED | ✅ |
| `hardware.devMode` | DEVICE.DEVELOP MODE / SYSTEM STATUS.IS DEVELOPMENT DEVICE | ✅ |
| `hardware.securityWarnings[]` | DEVICE EXTEND.SYSTEM SECURITY.TAMPER STATUS.REASON[] | ✅ |
| `network.*` | DEVICE EXTEND.NETWORK.{wifi,ethernet,cellular} | ✅（carrier 由 SIM 派生） |
| `settings.{timezone,language,autoTimezone,autoTime}` | DEVICE INFO.TIMEZONE/LANG + DEVICE EXTEND.SYSTEM SETTING.TIME | ✅ |
| `apps[].{name,version,installedAt,system}` | DEVICE APPLICATION.INSTALLED APPS.{appName,versionName,installationTimestamp,…} | ✅ 部分（缺多个标志位，见 §4.3） |
| `apps[].id` | —（合成主键） | 🟢 内部键，无碍 |

## 2. 🔴 超出模型的字段 / 模块（建议删除或下线）

这些在 UI 里出现、但模型没有对应定义，**违反"数据不能超越模型"约束**：

| # | UI 位置 | 内容 | 模型对应 | 处理建议 |
|---|---|---|---|---|
| E-1 | Basic · Device / Hardware posture；列表 Hardware 预设 | `macAddress`（设备级 MAC） | 无（模型仅有 nearby-wifi 的 MAC、SIM 的 IMEI） | 删除该列与该行；列表 "IMEI / MAC" 列改为只显 IMEI |
| E-2 | Basic · System（隐含） | `buildNumber` | 无（VERSION INFO 是分项版本，无单一 build 串） | 删除，或映射进 VERSION INFO（见 §3.4） |
| E-3 | **Monitoring · SIM data usage 卡片** | 月套餐 `capMb` / 账单周期 `billingResetsOn` / `daysToCap` / 30 天累计曲线 | 无套餐/账单概念；DEVICE STATISTIC 只有 mobile rx/tx/total bytes | 🔴 删除"套餐封顶/账单/预估到顶"叙事；如保留流量，改用 DEVICE STATISTIC 的真实 rx/tx/total（见 §3.5） |
| E-4 | **Monitoring · Memory 探针**（liveMemoryFor 进程列表） | 实时进程 + 每进程 MB | DEVICE INFO.MEMORY INFO 只有 total/used | 删除进程列表；保留 total/used 内存占用 |
| E-5 | Monitoring · runtime | CPU 占用 % | 无 | 删除 CPU 指标 |
| E-6 | Monitoring · Settings | `inputMethod`（输入法包名） | SYSTEM SETTING 只有 screen/media/time | 删除 |
| E-7 | **Apps & Firmware · Push history / Push app** | 设备指令下发历史（app-install/firmware push…） | 模型无"设备指令/下发"表；安装意图由 REQUEST APPS 表达，结果由 DEVICE EVENT 表达 | 🟠 重构：用 REQUEST APPS（目标）+ DIFF APPS（差异）+ DEVICE EVENT（结果）替代自造的 push 历史（见 §4.3） |
| E-8 | Apps & Firmware | 自造的"fleet 模板必装应用" `REQUIRED_APPS_DEFAULT` + `appDeltaFor` | REQUEST APPS / DIFF APPS 已是模型化的"应配应用 / 差异" | 🟠 改用模型字段（`DevicesTab` 已是此形态，可对齐） |
| E-9 | **Pre-warning Tab 整体**（traffic / geofence / disk 策略 + 事件） | 阈值策略与告警 | **本设备模型不含**；预警/地理围栏属契约 entitlement（GeoLocation / GeoFencing / Pre-warning） | 🟠 待定（见 §6 开放项 Q3）：本模型下无依据，是否保留/迁移到契约驱动？ |

## 3. 🟢 模型有、UI 缺，且明显归属本栏目的字段（建议补充）

模型对设备的刻画远比现状丰富。以下都属于"设备本身"的事实，建议在不改布局风格的前提下补进对应卡片/Tab：

### 3.1 DEVICE 表 · 身份与安全（缺）
- **CERT CN**（设备预装支付证书 CN，用于识别真实归属）→ Basic·Device 或 Hardware
- **CLIENT CERT**（CN / 公钥 / SHA1 / 过期日 / 颁发者）→ Hardware posture 新增"设备证书"行/小卡
- **CLIENT CERT CHANGE TIMES**（证书变更次数）
- **PCI VERSION**（PCI6 / PCI7）→ System 卡
- **RUN MODE**（UNATTENDED / ATTENDED）→ Basic（Monitoring 里已有 unattendedMode，可上提）
- **CREATION TYPE**（IMPORT / OA SYNC）+ **CREATION USER ID** → Basic·Device 的"来源/录入"
- TRANSFER KEY：偏内部密钥管理，**建议不在 UI 展示**（待确认）

### 3.2 DEVICE INFO 表 · 终端寿命计数器 & 物理状态（缺）
当前完全未展示，建议在 Monitoring 增一张"Usage counters / 终端使用统计"卡（沿用现有 StatTile 网格风格）：
- 刷卡/插卡/挥卡次数（CONTACT / CONTACTLESS / MAG STRIPE CARD READ COUNT）
- POWER CYCLE COUNT、POWER BUTTON PRESS COUNT、USB PLUG COUNT
- FRONT / REAR CAMERA OPEN COUNT、FLASH COUNT
- TOTAL PRINT LENGTH、TOTAL UP TIME（累计开机时长）
- **PRINTER STATUS**（正常/缺纸/过热…）→ Hardware / Modules
- **MEMORY INFO**（total/used）→ 替代 E-4 的进程列表
- **STORAGE INFO**（每存储芯片：厂家 / FW 版本 / 寿命）→ Hardware 子表（可选）

### 3.3 DEVICE INFO 表 · SIM 卡槽（现状单值，模型为双卡槽富字段）
- SIM SLOTS[]：SLOT INDEX、SLOT STATUS（EMPTY/ACTIVE/…）、ICCID、IMEI、IMSI、RSSI、IP ADDRESS
- 建议：Monitoring·Network 的 Cellular 区扩成"双卡槽"展示；IMEI 归到卡槽下（与 §4.2 一致）

### 3.4 DEVICE EXTEND 表 · 版本/电池保护/系统开关（缺）
- **VERSION INFO**（FIRMWARE ID / USER VERSION / FINANCE APP / FINANCE FIRMWARE / FINANCE BOOT / SIGNATURE LIBRARY / BSP / PAYMENT MODULE / BASEBAND）→ Apps & Firmware 或 System 增"版本明细"
- **BATTERY PROTECTION INFO**（充电保护开关 + 上下限）→ Monitoring（与电池相邻）
- SYSTEM STATUS 里缺的：USB HOST SWITCH、HOTSPOT MENU SWITCH（现仅有 statusBarPulldown）
- SYSTEM CONFIGURATION / SYSTEM PARAMETERS（服务端下发参数）→ State 卡已有 sysParams，可对齐字段名

### 3.5 BATTERY INFO / DEVICE STATISTIC / DEVICE APPLICATION STATISTIC（大块缺失，归属待确认）
模型里有三张"重"表，现状几乎未用：
- **BATTERY INFO**：循环次数、健康度%、温度、内阻、生产日期、充电方式、是否正品、安全等级、充电保护…（现仅 level + 粗粒度 health）
- **DEVICE STATISTIC**：按日的刷卡数 / 打印长度 / 开机时长 / 各网卡 rx-tx-total 流量 / 前台时长 / 定位成功失败
- **DEVICE APPLICATION STATISTIC**：每应用的流量 + 前台使用时长
- 这三者**信息量大**，可能更适合放到独立的 *Battery Health* / *Device Health* 菜单（参考 `_refsrc` 里 Support 下确有 Device Health / Battery Health）。
- 决策点见 §6 开放项 **Q1/Q2**：哪些进 Devices→Devices 详情，哪些归兄弟菜单？

## 4. 🟠 语义 / 命名需要对齐的点

### 4.1 设备 STATUS 编码错位（重要）
- 模型 DEVICE.STATUS = **1 正常 / 0 锁定 / 9 待激活**。
- 现状 `state` = **active / inactive / pending**，其中 `inactive` 实为"离线/久未签到"，模型里**离线不是一种 STATUS**（在线/离线应由 last-seen 派生）。
- 模型的"锁定(Locked)"目前只埋在 Monitoring 的 `terminalLocked`，列表/详情头部没有体现。
- 建议：把"**状态**"拆成两个维度——
  - **STATUS**（Normal / Locked / Pending activation）来自 DEVICE.STATUS + DEVICE EXTEND.LOCK STATUS；
  - **在线度**（Online / Offline）由 last-seen 派生，仅作展示，不作 STATUS。
- 影响：列表 Status 列、详情头部 pill、搜索筛选项。**仅改语义与取值来源，不改 pill 视觉**。

### 4.2 IMEI 归属
- 模型 IMEI 在 SIM SLOTS 下、每卡槽一个；现状是设备级单值 `imei`。
- 建议：保留列表/Basic 的"主 IMEI"展示（取 ACTIVE 卡槽），Monitoring 展开双卡槽明细。

### 4.3 已安装应用 / 应配应用字段（决策：以 REQUEST 为中心、不用 DIFF）
- INSTALLED APPS 模型字段：pkgName、appName、versionCode、versionName、installationTimestamp、isUninstallable、isAutoStartOnBoot、isKioskMode、isAppLaunchDisabled、isLauncherIconHidden。现状只用了 name/version/installedAt + 自造 `system`。
  - 补 pkgName（包名，模型主用键）、versionCode + 标志位。
- **REQUEST APPS（应配）为中心**；**DIFF APPS 不使用**（每行状态由 REQUEST vs INSTALLED + 最近 EVENT 现场派生）。INSTALLED = REQUEST 中应用的最终结果。详见 §9.4。

### 4.4 DEVICE EVENT 事件类型
- 模型 EVENT TYPE 枚举：应用开始下载/下载成功/下载失败/安装失败/安装成功/用户取消升级/用户确定升级/卸载成功/应用不存在无法删除（+ OTA 固件）。
- `devices-tab.jsx` 的 `_EVENT_META` 已基本对应；fleet Monitoring 的 `eventsFor`（boot/install/network 自造）需对齐到模型枚举 + target1/2/3 字段。

## 5. 🟡 终端 ↔ 商户 / 门店 关系（按指示只保留关系，不展开）

- 模型：DEVICE.**PARTNER ID** = 设备真实所有者主体；门店绑定经"激活"建立；划拨改变所有者、委托改变运营方但不改所有者。STORE.**MERCHANT PARTNER ID** = 门店所属商户。
- 现状：设备直接挂 `merchantId` + `storeId`，详情/列表展示"Bound to {merchant} · {store}"。
- 处理：
  - **保留**现有 `merchantId`/`storeId` 作为"绑定门店及其商户"的关系展示，**不新增**所有者/划拨/委托相关字段与流程（关系定义未定且会变）。
  - 仅做一处澄清：明确"PARTNER ID（所有者）"与"门店所属商户"在模型中是两个概念，本期 UI 暂以门店绑定为准、不渲染所有者维度。
  - STORE 表其余字段（country/timezone/phone/operators…）不属于 Devices→Devices，本栏目不引入。

## 8. 业务方决策（2026-06-06）

| # | 议题 | 决策 |
|---|---|---|
| 0 | DEVICE.PARTNER 的含义 | **PARTNER = ISO**（设备所有者是 ISO）。门店/商户是"部署位置"，与所有者 ISO 是两个维度。本期仍以现有 `merchantId/storeId`（部署绑定）展示，不展开所有者/划拨/委托。 |
| 1 | 电池 | **只保留电池健康度 + 电量**（BATTERY HEALTH + BATTERY AVAILABLE）。BATTERY INFO 其余字段、BATTERY PROTECTION INFO 本期不做。 |
| 2 | DEVICE STATISTIC / DEVICE APP STATISTIC | **本期不做历史统计表**，只显示"当日数据"（当前快照值）。→ 删除 30 天曲线 / 多日对比；位置成功失败只留"今天"。 |
| 3 | Pre-warning Tab | **整体去掉**（连同 `prewarningFor` / `prewarningEventsFor` / `PREWARNING_POLICIES` / `DevicePrewarningTab` 及详情头部的 critical 角标）。 |
| 4 | Push history | **改为迁移 Monitoring 的 Event log**：用模型 DEVICE EVENT 替换自造的 `pushHistoryFor`；Monitoring 不再有 Event log。 |
| 5 | CLIENT CERT | **在 Basic information 新增 "Client cert" 栏**展示设备证书；**TRANSFER KEY 不展示**。 |
| 6 | STATUS | **拆成两维**：STATUS(Normal / Locked / Pending activation) + 在线度(Online / Offline，由 last-seen 派生)。 |

## 9. 落地清单（据 §8）

### 9.1 Seed（`DEVICES_SEED`）调整
- **删**：`buildNumber`、`macAddress`。
- **改**：`battery` → `{ level, health }`，其中 `health` 由枚举改为**健康度百分比**（BATTERY HEALTH，0–100）。
- **改**：`state` 拆为 `status`(`normal`|`locked`|`pending`) + 派生 `online`(由 `lastSeenAt`)。`pending` = 待激活(9)；`locked` = 锁定(0)；其余 = 正常(1)。
- **增**（DEVICE 身份/安全）：`certCn`、`clientCert{cn, sha1, expiredDate, issuerCn, publicKey?}`、`clientCertChangeTimes`、`pciVersion`(PCI6|PCI7)、`runMode`(UNATTENDED|ATTENDED)、`creationType`(IMPORT|OA_SYNC)、`creationUserId`。
- **增**（DEVICE INFO 当日/当前快照）：寿命计数器（刷/插/挥卡、开关机、电源键、USB、前后相机、刷机、打印长度、累计开机）、`printerStatus`、`memory{total,used}`、`simSlots[]{slotIndex,slotStatus,iccid,imei,imsi,rssi,ip}`。
- **增**（DEVICE EXTEND）：`versionInfo{firmwareId,userVersion,financeApp,financeFirmware,financeBoot,signatureLib,bsp,paymentModule,baseband}`、`systemStatus` 补 `usbHostSwitch`/`hotspotMenuSwitch`。
- IMEI：保留设备级"主 IMEI"（取 ACTIVE 卡槽），`simSlots` 提供双卡明细。

### 9.2 Basic information Tab
- Device 卡：删 build/MAC 相关；**删 IMEI 行**（决策：IMEI 归 Monitoring 的双卡槽，Basic 不展示）；补 CERT CN、PCI version、Run mode、Creation type/user。
- **新增 "Client cert" 卡/栏**：CN、SHA1、有效期、颁发者 CN（+ 变更次数）。TRANSFER KEY 不展示。
- **新增 "Version info" 卡**（决策：VERSION INFO 版本明细放 Basic）：FIRMWARE ID / USER VERSION / FINANCE APP / FINANCE FIRMWARE / FINANCE BOOT / SIGNATURE LIBRARY / BSP / PAYMENT MODULE / BASEBAND。
- System 卡：保留 OS/Firmware/Timezone/Language/Auto*；版本明细已移至 Version info 卡。
- Hardware posture：删 MAC address 行；Root/Dev/Tamper 保留。

### 9.3 设备首页列表 —— 展示与分类分析（决策 #4）

**现状机制（保留，不改样式/布局）**：列表恒定 `SN`(锁左) + 预设列 + `Status`(锁右)，配 5 个**列预设**（Overview / Network / Security / Hardware / Apps）做"分类切换"，外加"Manage columns"自定义抽屉 + Saved views。本质上**预设 = 分类**，无需新造机制——本次只把"列目录"按新模型重新策展。

### 9.4 Apps & Firmware Tab
- **以 REQUEST APPS 为中心**（决策补充 2026-06-06）：
  - **不使用 DIFF APPS 字段**；**不再做** `REQUIRED_APPS_DEFAULT` / `appDeltaFor` 自造模板，也不做 Missing/Outdated/Installed 三表拆分。
  - 列表数据 = 该设备的 **REQUEST APPS**（ISO 为本机配置的应用）。每行展示该应用的"最终结果" = INSTALLED 中对应包名的实际版本（`installed 是 request 中应用的最终结果`）。
  - 每行状态由 REQUEST(目标版本) vs INSTALLED(实际版本) + 最近 DEVICE EVENT 派生（installed / needs upgrade / not installed / downloading / failed），即复用 `deriveAppStatus` 形态（与 `devices-tab.jsx` 的 Configured-apps 一致）。
  - 每行可展开/点出 STRATEGY（upgradeStrategy / networkRequest / upgradeTime / cellularCap / installWindows）。
  - INSTALLED APPS 字段保留 pkgName / versionCode / versionName / installationTimestamp + 标志位（isUninstallable / isKioskMode / isAutoStartOnBoot / isAppLaunchDisabled / isLauncherIconHidden），但仅作为"REQUEST 行的实际结果"来源，不再单列完整安装清单表。
- **Push history → Event log**：用 DEVICE EVENT（model eventType 枚举 + target1/2/3 + eventDuration）。**删** `pushHistoryFor`。事件类型对齐模型（应用下载/安装/卸载/用户动作/OTA），**丢弃** boot/net-change（不在模型枚举内）。
- Firmware 卡：保留（当前/目标版本），可并入 VERSION INFO 明细。
