# Catalog 选购 — 业务流程与规则

Catalog 是平台运营**替客户下单**的前台：浏览在售商品 → 进商品详情选选项和数量 → 加入购物车 → 走结算向导生成一张订单。它不是客户自助商城，而是 Sales 域里运营用的下单工具。Catalog 只负责"挑货、组单"，挑的货来自 Products 目录，组出的单交给 orders 模块去收款发货。

> 状态：核心行为已与业务确认。要点：Catalog 是运营替客户下单的前台、属 Sales 域只 ADMIN 可用；任意状态客户都能下单；只挑得到在售商品+在卖 SKU、无库存；下单按当时 SKU 快照建订单行、**单价仅在结算页可逐行任意改**（含高于目录价与改成 0、无额外权限）；合计为 0 的免费单无需审批、直接待发货；结算必选是否样机；购物车按浏览器本地留存（换设备/清缓存即丢）。无遗留开放问题。

## 1. 后台处理与跨模块业务规则（重点）

### **RULE-CAT-01** 〔确认〕

Catalog 是运营**替客户下单**的入口，必须先选一个客户公司，订单的计费与收货都归这个客户。
  - 结算向导里有一步专门选客户公司；选定后收货人 / 收货地址默认带出该客户的 Admin 操作员与公司地址，可改。
  - **任意状态的客户都能下单**：选客户时会显示客户状态（Active / Onboarding 等）作参考，但不拦截，给 Onboarding / 未激活客户也能下单。
  - 整个 Catalog 属于 Sales 域，只在平台 ADMIN 后台操作、客户侧看不到（继承 RULE-PRD-12 的 Sales 域权限基线）。

### **RULE-CAT-02** 〔确认〕

只挑得到在售的货：浏览、商品详情、加购都只列在售商品 + 在卖 SKU，无库存 / 无缺货态。
  - 浏览页只显示"上架（ACTIVE）"商品；商品详情和选项只列在卖的 SKU；下架商品和已停售存档 SKU 都进不来（消费 Products 的门控，见 RULE-PRD-04）。
  - 没有库存概念，凡是列出来的都可下单，不出现"缺货 / 售罄"。

### **RULE-CAT-03** 〔确认〕

下单按**当时的商品信息建订单订单行**，单价仅在**结算页**可逐行手填覆盖目录价。
  - 加入购物车 / 直接下单时，按那一刻的 SKU 把名称、属性、图片、单价**快照**进订单订单行；这是 RULE-PRD-03 的下单侧。
  - 单价默认取 SKU 目录价。**改价只发生在结算页**（结算第一步的逐行单价输入框）；商品详情页与购物车都只读显示价、不能改。覆盖价随订单行一起快照进订单。
  - 改价**无上下限、无额外权限**：可低于、等于或高于目录价，也可改成 0。

### **RULE-CAT-04** 〔确认〕

结算提交时把购物车整理成一张订单，落到 orders 模块。
  - 提交时把购物车每个订单行 + 所选客户 + 收货信息 + 折扣 + 订单类型，组装成一张订单，生成订单号（形如 SO-年份-四位流水），交给 orders 模块。
  - 提交成功后清空购物车，并提示订单已创建、去向（待付款 / 待发货）。

### **RULE-CAT-05** 〔确认〕

下单金额决定走不走收款：**合计为 0（满折 / 免费）直接进待发货、跳过付款**；合计大于 0 进待付款。
  - 折扣有两种、**二选一互斥**：按比例（0–100%）或按固定金额；同一单只能用一种。
  - 满折（100% 或折到 0）即"免费单"，合计为 0。
  - 合计为 0 → 新订单直接是"待发货"，无需收款、**无需审批**；合计大于 0 → "待付款"。

### **RULE-CAT-06** 〔确认〕

结算必须明确**是不是样机订单**，无默认值。
  - 结算第一步强制回答"是否样机订单"（样机 / 量产），不选不能继续。
  - 样机 / 量产是订单的属性、不在商品上（呼应 RULE-PRD-10）；同一件货既能下成样机单也能下成量产单。两者后续差异（如发货绑定设备）见 orders 模块。

### **RULE-CAT-07** 〔确认〕

购物车会**跨刷新留存**；同商品同 SKU 再加会合并数量。
  - 购物车内容在浏览器本地留存，刷新 / 重进不丢；下单成功后清空。
  - 往车里加已存在的"同商品 + 同 SKU"订单行时，合并为一行、数量累加，并以新加入的覆盖价为准。
  - 购物车按**浏览器本地**留存：换设备 / 清缓存即丢、同账号多端不同步——这是当前现状。

**跨模块边界指针：**
- 订单创建之后的收款、发货、样机绑定设备、取消 / 退款 → 见 **orders 模块**。
- 可挑选的商品、SKU、分类、上下架与改价规则 → 见 **products 模块**。
- 所有变更记审计 → 继承 RULE-PRD-13 的全系统审计基线（下单创建订单同样记录）。

## 2. 业务规则（本模块自身 / 界面骨架）

### **RULE-CAT-08** 〔确认〕

浏览页：分类标签栏（最多两级）即时筛选 + 本页商品搜索。
  - 顶部一排分类标签（最多展开到二级），点一下即时筛选；另有本页搜索框，只按商品名 / 描述搜，不搜 SKU 编码。
  - 只显示在售商品（见 RULE-CAT-02）。

### **RULE-CAT-09** 〔确认〕

商品详情页：看图、选选项、填数量，加入购物车或直接下单。
  - 展示图片、描述、规格；多 SKU 商品按"选项（Options）"选取属性取值，单 SKU 直接可买。
  - 可填数量；**改价不在此页、放到结算页**（见 RULE-CAT-03）。提供"加入购物车"和"直接下单"两条路。

### **RULE-CAT-10** 〔确认〕

购物车：逐行改选项 / 改数量 / 移除 / 清空，可"再加一个"同商品的别的选项。
  - 订单行可改选项（换到同商品的另一个在卖 SKU）、改数量、移除；可一键清空（带二次确认）。
  - **改价不在购物车**，统一放到结算页（见 RULE-CAT-03）；购物车里单价只读显示。
  - "再加一个"用于把同一商品的另一个选项作为新行加入。

### **RULE-CAT-11** 〔确认〕

结算向导三步：① 商品与数量 + 是否样机 + 折扣 ② 客户与收货 ③ 复核并创建。
  - 至少保留一个订单行才能结算（不能把最后一行也删掉）。
  - 三步走完点"创建订单"生成订单（金额分流见 RULE-CAT-05、客户与收货见 RULE-CAT-01）。
