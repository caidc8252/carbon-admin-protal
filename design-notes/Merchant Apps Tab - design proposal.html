Design proposal · v1 · review before build

Customer Detail → Apps tab (MERCHANT contracts)

Hybrid of the original MerchantAppsTabRO (row-expand + pending banner + per-terminal table) and the new App Pool model (PARTNER_APPLICATION + MERCHANT_APPLICATION + DEVICE_APP_STRATEGY). Below uses Bluefin Market (c-007) as the demo — 3 provisioned apps, 14 terminals, each app on a different rollout shape (bulk-aligned · bulk-rolling · per-terminal).

What's different from the version I shipped (and removed)
  • KEEP — single table, row click expands, "N of M pending" banner, on-target collapse, per-terminal table inside (the original UX).
  • ADD — Publisher (ISV) + Source (Upload / Subscription) columns sourced from PARTNER_APPLICATION + APPLICATIONS.
  • ADD — Approved-version "↑ upstream X.Y.Z" lag indicator when the ISO has approved an older PAV than the upstream latest (POS Pro 4.3.1 vs 4.3.2 demo case).
  • ADD — Strategy column shows a single "Bulk · ⤴ Reboot" chip for uniform rollouts, "Mixed (3 variants)" for per-terminal — clicking opens the strategy modal.
  • DROP — separate Coverage column from my removed version. Coverage is now compact (X/Y on target + tiny bar) so it can live in the Terminals column, freeing a slot for Source.
  • DROP — separate KPI strip from my removed version. Replaced with a single 1-line summary above the table — the apps table is already a scannable summary; an extra strip was redundant.

A
Read-only label is one line, not a banner
Admin's only job here is to look. The "maintained by <ISO>" hint lives in the summary row in fg3 — no banner needed.
B
Source pill distinguishes UPLOAD vs SUBSCRIPTION
From PARTNER_APPLICATION.source. Upload = ISO self-published; Subscription = ISO subscribed to another ISV's app. Affects nothing functional in this read-only view but matters for operator mental model (escalation paths differ).
C
Coverage merged into Terminals column
Numeric (X / Y) + tiny bar in one cell. Saves a column. Color = success / info / warning by % on target.
D
Strategy chip is the entry to detail modal
Bulk · Reboot = uniform across all terminals. Mixed · N variants = at least one terminal differs. Click → strategy detail modal (see §3).
E
Status derives from upstream + ma.status
If the upstream APPLICATIONS.status flips to UNPUBLISHED / ARCHIVE, this column shows "Unpublished upstream" (amber). Otherwise ma.status.

F
Two-card summary head
Strategy summary (left) explains uniformity; Versions card (right) shows approved vs upstream lag. Both surface info that was buried in the original "How they'll upgrade" line.
G
Target column highlights drift
When installed ≠ target, Target renders in warning bold mono. On-target rows render Installed = Target in default fg.
H
SN is the only clickable
Per the previous round, clicking SN opens that terminal's device-detail page with Back returning to customerDetail/apps (extend the __openTerminalFromCustomer contract with tab='apps').
I
No bulk-summary banner for mixed
Unlike Smart Receipt (§1) — that had a pending-rollup banner because the strategy was uniform. For mixed, the banner would be misleading, so we collapse to "3 distinct variants" + the per-row truth.

?Questions before I build

  1. Source pill placement — is it OK as its own column, or do you want it folded into the Application cell as a subtitle chip (less visual weight)?
  2. "Mixed (3 variants)" affordance — currently the chip itself is the trigger, but for mixed rows that's a dead-end (the modal would just say "expand the row"). Options: (a) chip is non-interactive when mixed; (b) chip says "Expand to view" and scrolls the row open. I'd vote (a).
  3. Version-lag chip — the demo case is c-014 POS Pro: ISO approved 4.3.1, upstream is 4.3.2, ISO explicitly SKIPped 4.3.2. Show "↑ 4.3.2 upstream · skipped by ISO" in amber, or just "↑ 4.3.2 upstream"? Skipped feels like useful context for admins.
  4. Status column — original tab didn't have one. Worth keeping for the upstream-unpublished case, or drop?
  5. KPI strip — I removed it; the 1-line summary above the table now does the same job in 12% of the vertical space. OK?
