Design proposal · v4.1 · column-order tweak + last-seen rename

Customer detail · Devices tab

Devices tab = device table only. No KPI strip, no store chips, no behavior flags. Apps appear inside the row-expansion with the original Apps-tab idiom: target/installed mono versions + status pill + strategy chip → modal. Events open via a per-row text link.

Changes from v3 (per your feedback round 2)
  • Top summary line + store chip filter — removed. Tab now opens straight to the device table.
  • Behavior flags (KIOSK / BOOT / LOCKED / HIDDEN) — pulled from the row entirely. Re-add later if needed.
  • Inline strategy fragment ("CASUAL · Wi-Fi only · 02:00–04:00") in the expanded sub-table — gone. Only the strategy chip remains; click to inspect.
  • Strategy chip → modal — mirrors the original MerchantAppsTabRO pattern. The chip itself shows just the urgency (CASUAL/IMMEDIATE/CUSTOM); the modal lays out network, install time, cellular cap, install windows.
  • Status pill borrows from original Apps tab — _TERM_STATES equivalents: Installed · Awaiting · Downloading · Failed · Not installed. Derived per app per device using REQUEST_APPS vs INSTALLED_APPS + latest DEVICE_EVENT.
  • "View events" as a right-aligned text link in each row, not a button.
  • Kept — empty state "未添加任何终端", row expansion, single "Configured apps" sub-card with one row per configured app.
Tweaks since v4 (round 3)
  • Sub-table column order — now App · Installed · Target · Strategy · Status. Installed leads ("what's actually there"); Status is computed at the right.
  • Device-table "Last sync" → "Last seen" — terminology aligned with the device's last self-report timestamp.
  • Strategy chip stays urgency-only, no network suffix — settled per your previous answer.

A
No chrome above the table
Tab body opens directly to the device list. No "all stores" filter, no KPI tiles, no summary line. If admin needs to filter by store, that's a future affordance — not v1.
B
"Configured apps" column = count + 1-word hint
Three states: all installed · N to install · N install failed · no sync yet. The number is the count of REQUEST_APPS entries (constant per device); the hint is the only thing that changes.
C
"View events" text link
Right-aligned per row; opens the events modal (§3) for that one terminal. Greyed when there's no sync yet.
D
Status pill = original _TERM_STATES
Installed (green) · Needs upgrade (amber) · Downloading (info) · Failed (red) · Not installed (neutral). Derived from REQUEST vs INSTALLED + latest DEVICE_EVENT for that pkg.
E
Strategy chip is the only strategy surface
Shows urgency only (CASUAL / IMMEDIATE / CUSTOM). Network / cell cap / install windows live in the modal (§2). Mirrors the original Apps-tab pattern.
