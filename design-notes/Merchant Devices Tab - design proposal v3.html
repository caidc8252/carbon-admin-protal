Design proposal · v3 · simplified per feedback

Customer detail · Devices tab

Devices tab shows the terminals registered to a MERCHANT customer + the apps the ISO has configured for each. The configured-apps list is the only app surface; install state is shown beside each row by reconciling REQUEST_APPS with the device's INSTALLED_APPS at render time. No KPIs, no DIFF concept exposed, no merchant-level app aggregation. Events live behind a per-row modal.

Changes from v2 (per your feedback)
  • KPI strip — removed entirely. The table is the surface; aggregate counts live above as a single muted line if needed.
  • DIFF as a visible concept — gone. We never use the word "diff". Reconciliation happens silently behind the per-row "Installed?" cell.
  • Recent events inline — removed from the expanded body. Now lives in a per-row Events button that opens a modal.
  • Configured apps is now the only sub-card in the expanded body. Each app row joins REQUEST + INSTALLED, showing version + install state in one line.
  • Empty state = single text line "未添加任何终端" — no illustration, no CTA (apps + terminals are added on the customer-side ISO portal, not here).
  • Kept — store chip strip, SN deep-link to device-detail, behavior flag chips on installed-app rows.

A
No KPI strip
Per your feedback. The one-line summary above the store strip gives the only counts admin needs at a glance.
B
"Configured apps" cell is the only app surface
Count of REQUEST_APPS entries + a 1-word hint when reconciliation finds gaps: all installed / N to install / no sync yet. No "diff" terminology.
C
Per-row Events button → modal
Right-aligned action. Greyed/disabled for never-synced devices. Opens the events modal (§3) for that one terminal.
D
"Installed?" is plain English, 1 of 4 states
Installed (req.code = inst.code) · Needs upgrade (inst.code < req.code) · Not installed (no matching pkg) · — (device never synced). The version cell uses req → inst so admins read it left-to-right.
E
Behavior flags only on actually-installed rows
Flags come from INSTALLED_APPS. If the app isn't installed yet, there's nothing to flag → cell shows "—".

G
Modal, not drawer
Events are a focused inspection action — modal feels right and stays cheap. Width 680 px so descriptions don't wrap.
H
Filter chips along the top
Groups the EVENT_TYPE enum into 4 buckets: Install (success/fail), Download (start/succ/fail), User action (cancel/confirm), OTA. Default = All, last 7 days.
I
Event row = 3 columns + duration
Time (mono) · status dot · body (English + mono pkg) · duration (right-aligned, mono). EVENT_DURATION only renders when present.
J
Load more (paginated)
Initial = 50 events; "Load more" appends 50 at a time. We don't expose a full export — admin can deep-link to the device-detail Events tab for that.
